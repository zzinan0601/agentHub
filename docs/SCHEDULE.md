# 스케줄 - 정해진 시각에 대신 질문하기

대화방마다 스케줄을 **하나** 걸 수 있다. 시간이 되면 저장해 둔 질문을 코디네이터가 대신
던지고, 결과가 그 방에 쌓인다. 화면을 새로고침하지 않아도 나타난다.

`schedules` 테이블의 기본키가 `room_id` 라서 "방당 1개" 는 DB 가 보장한다.
새로 저장하면 추가가 아니라 **교체**된다.

---

## 거는 방법

오른쪽 패널 아래 **스케줄** 을 펼친다.

1. 프리셋 버튼을 누르거나 cron 식을 직접 입력한다
2. 그 시각에 던질 질문을 적는다
3. 저장

입력하는 동안 **실제 실행 시각 3개가 미리 표시된다.** "3시간마다" 가 맞게 걸렸는지
글로 된 설명 대신 시각으로 확인하면 된다.

---

## cron 식

표준 5칸 crontab 형식이다. 시간대는 `.env` 의 `TIMEZONE`(기본 `Asia/Seoul`)을 따른다.

```
분  시  일  월  요일
0   9   *   *   1-5     ← 평일 오전 9시
```

| 기호 | 뜻 | 예 |
| --- | --- | --- |
| `*` | 매번 | `* * * * *` = 1분마다 |
| `*/n` | n칸마다 | `0 */3 * * *` = 3시간마다 |
| `a-b` | 범위 | `0 9-18 * * *` = 9시부터 18시까지 매시 |
| `a-b/n` | 범위 안에서 n칸마다 | `0 9-18/2 * * *` = 9,11,13,15,17시 |
| `a,b,c` | 나열 | `0 9,13,18 * * *` = 하루 3번 |

요일은 `0`(일) ~ `6`(토) 이다.

### 자주 쓰는 것

| 원하는 것 | cron |
| --- | --- |
| 30분마다 | `*/30 * * * *` |
| 1시간마다 | `0 * * * *` |
| 3시간마다 | `0 */3 * * *` |
| 6시간마다 | `0 */6 * * *` |
| 매일 오전 9시 | `0 9 * * *` |
| 평일 오전 9시 | `0 9 * * 1-5` |
| 평일 업무시간 2시간마다 | `0 9-18/2 * * 1-5` |
| 매주 월요일 오전 8시 | `0 8 * * 1` |
| 매월 1일 오전 9시 | `0 9 1 * *` |

> **"n시간마다" 는 시(時) 칸에 `*/n` 을 넣고 분 칸을 고정하는 것이다.**
> `*/3 * * * *` 는 3시간이 아니라 **3분**마다다. 분 칸이 앞이라는 점을 헷갈리기 쉽다.
> 미리보기의 실행 시각을 보면 바로 알 수 있다.

### 쓸 수 없는 것

`@hourly`, `@daily` 같은 확장 문법과 초 단위 6칸 형식은 지원하지 않는다. 5칸만 쓴다.

---

## 실행될 때

- 예약된 질문이 **"예약" 배지**와 함께 대화에 남고, 그 아래에 결과가 붙는다.
- **다른 방을 보고 있어도 알 수 있다.** 결과가 쌓인 방은 왼쪽 목록에서 청록 점과 함께
  밝게 표시되고 `+N` 이 붙는다. 상단 띠의 `Chat` 옆에도 합계가 뜨므로 Dashboard 를
  보고 있을 때도 놓치지 않는다. **그 방을 열면 표시가 사라진다.**
- 그 방의 에이전트 선택·실행 방식·워크플로우 설정을 그대로 따른다.
  워크플로우와 묶으면 매번 같은 순서로 도는 정기 보고서가 된다.
- 코어가 잠깐 꺼져 있었어도 5분 안이면 다시 뜰 때 실행한다 (`misfire_grace_time`).
- 코어를 재기동하면 DB 에 저장된 스케줄이 자동으로 다시 등록된다.

## 끄고 지우기

**삭제** 를 누르면 없어진다. 잠시 멈추고 싶을 뿐이라면 API 로 `enabled: false` 를 보낼 수도 있다.

---

## 주기가 응답 시간보다 짧으면

앞 실행이 끝나기 전에 다음 차례가 오면 **그 차례는 건너뛴다.** 겹쳐서 돌리면 같은 에이전트를
두 번 부르게 되고, 로컬 모델은 그러면 둘 다 느려지기 때문이다.

건너뛴 사실은 조용히 넘어가지 않는다. 그 대화방에 한 줄로 남고 Dashboard 의 **점검 대상**에도
개수가 뜬다. 이 숫자가 쌓인다면 주기가 응답 시간보다 짧다는 뜻이므로 cron 을 늘려야 한다.

사람이 그 에이전트를 쓰고 있을 때도 마찬가지로 비켜주고 기록을 남긴다.
