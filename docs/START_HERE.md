# 시작하기 — 30분 안에 내 에이전트 붙이기

우리가 만드는 것은 **사내 채팅 화면 하나에서 열 명의 업무 에이전트를 함께 부르는 플랫폼**이다.
사용자는 채팅창에 질문을 던지고, 코디네이터가 어느 에이전트를 부를지 정해 결과를 합쳐준다.

여기서 각자가 맡는 것은 **자기 업무 에이전트 하나**다. 화면도, 라우팅도, 스케줄도,
스트리밍도 이미 되어 있다. 만들 것은 "내 업무 데이터를 조회해 Markdown 으로 돌려주는
함수 하나" 다.

---

## 왜 계약(contract)이 있나

코디네이터는 열 개의 에이전트를 **똑같은 방식으로** 부른다. 그래야 한 화면에서
단일·병렬·순차 호출이 가능하다. 그래서 모든 에이전트는 같은 HTTP 규약을 지킨다.

다행히 **계약을 직접 지킬 필요는 없다.** 템플릿의 `main.py` 가 대신 지켜준다.
계약 위반이 구조적으로 어렵게 만들어져 있고, 그 파일은 건드리지 않는다.

| 파일 | 누가 고치나 |
| --- | --- |
| `main.py` `contract.py` `llm.py` `files.py` | **아무도 안 고친다** (계약 고정부) |
| `manifest.yaml` | 나 — 자기소개 |
| `agent.py` | 나 — 업무 로직 |
| `prompt.md` `.env` `requirements.txt` | 나 |

---

## 다섯 단계

```bash
python scripts/new_agent.py <내-에이전트-id> "<내 이름>"
```

1. **폴더 만들기** — 위 명령이 `agents/<id>/` 를 통째로 만들어 준다.
   포트는 **전원이 9010 으로 같다.** 에이전트마다 노트북이 다르므로 IP 가 이미 서로를
   구분한다. 나눠 가질 필요가 없고, 방화벽도 한 포트만 열면 된다.
2. **`setup.bat`** — 가상환경과 의존성. 최초 1회.
3. **`manifest.yaml` 채우기** — 아래 "가장 중요한 것" 참고.
4. **`agent.py` 의 `fetch_business_data()` 채우기** — 오라클이든 PostgreSQL 이든 사내 API 든 자유.
   Markdown 표 문자열로 돌려주면 뒤가 편하다.
5. **`run.bat` 으로 띄우고 자가검사** —

```bash
python scripts/check_contract.py http://localhost:9010
```

전 항목 `OK` 면 [registry.yaml](../registry.yaml) 에 한 줄 추가한다.
30초 안에 화면 오른쪽 목록에 초록 점과 함께 나타난다. 코어를 재기동하지 않아도 된다.

> 아무것도 안 고친 상태의 템플릿도 자가검사를 통과한다. **먼저 띄워서 초록 점을 본 다음**
> 업무 로직을 채우는 편이 막힐 일이 적다.

## 가장 중요한 것 — `description`

사용자가 화면에서 에이전트를 직접 고르지 않으면, **코디네이터 LLM 이 `description` 과
`examples` 만 읽고** 누구를 부를지 정한다. 이 두 줄이 곧 라우팅 품질이다.

```yaml
# 나쁜 예 — 다른 에이전트와 구분되지 않는다
description: 매출을 조회한다.

# 좋은 예 — 무엇을 / 어떤 기간·단위로 / 어떤 형태로
description: |
  영업 오라클 DB 의 일별 매출 테이블을 조회해 기간별·지점별 매출 합계와
  전월 대비 증감을 Markdown 표로 정리한다. 최대 조회 기간은 12개월이다.

examples:
  - 지난달 지점별 매출 알려줘
  - 3월 매출 상위 10개 지점은?
```

Dashboard 의 **점검 대상**에 "한 번도 안 불림" 으로 뜨는 에이전트는 거의 항상
`description` 이 모호한 경우다.

## 지켜야 할 네 가지

폐쇄망으로 반입할 결과물이라 아래는 예외가 없다.

1. **설정을 코드에 쓰지 않는다.** 접속 정보·주소·포트·모델명 전부 `.env` 로 뺀다.
2. **`requirements.txt` 는 전 항목 `==` 로 버전을 고정한다.** 반입 시점에 버전이
   달라지면 그대로 죽는다.
3. **외부 인터넷에 의존하지 않는다.** CDN, 공개 API, 런타임 다운로드 전부 폐쇄망에서 끊긴다.
4. **계약 고정부 4개 파일을 고치지 않는다.**

## 알아둘 것

- **에이전트는 각자 자기 노트북에서 돈다.** 노트북을 끄면 목록에 회색 점으로 바뀌고
  그 사람 에이전트만 빠진 채 나머지로 답이 나간다.
- **첨부파일도 내 노트북에 남는다.** 코어가 중계만 하고 캐시하지 않으므로, 노트북이 꺼지면
  과거 대화의 파일도 열리지 않는다. CSV 는 반드시 `save_text()` 를 쓴다 — 엑셀에서
  한글이 깨지지 않게 BOM 을 붙여준다.
- **응답이 오래 걸리면 `yield status(...)` 를 자주 보낸다.** 로컬 모델이라 수십 초가 예사인데,
  아무것도 안 보내면 화면이 멈춘 것처럼 보인다.
- **순차로 부를 때의 순서는 사람이 정한다.** 직접 고르면 고른 순서, 자동이면 라우터가
  정한 순서, 워크플로우면 yaml 의 `steps` 순서다. 화면 오른쪽 `실행 방식 > 호출 순서` 에서
  ↑↓ 로 바꿀 수 있다. **순차에서는 마지막 에이전트의 결과가 곧 답**이므로, 다듬는 역할을
  맡은 에이전트를 뒤에 둔다.
- **내 에이전트가 호출 중이면 다른 사람은 못 부른다.** 같은 Ollama 를 나눠 쓰면 둘 다
  느려지기 때문에, 화면에 주황색으로 표시되고 잠긴다.

## 제출 기준

아래 여섯 개가 전부다. 이것만 통과하면 코디네이터가 알아서 부른다.

- [ ] `python scripts/check_contract.py <내주소>` 전 항목 통과
- [ ] `manifest.yaml` 의 `description` 이 구체적이고 `examples` 가 2개 이상
- [ ] 계약 고정부 4개 파일을 고치지 않음
- [ ] 접속 정보·모델명을 `.env` 로 뺌 (하드코딩 0건)
- [ ] `requirements.txt` 전 항목 `==` 버전 명시
- [ ] `registry.yaml` 에 등록하고 화면에서 초록 점 확인
